DeepSeek Harness Web

Self-contained container image, published to this repository's GHCR namespace.

The dsh web container runs the browser surface of DeepSeek Harness without a checkout or a Node toolchain. Each image ships the built server and frontend on node:22-slim; the server listens on port 3080.

Quick start

docker pull ghcr.io/opscalehub/deepseek-harness:latest
docker run -d --name dsh-web -p 3080:3080 -v dsh-data:/root/.dsh \
  ghcr.io/opscalehub/deepseek-harness:latest

Then open http://localhost:3080 and choose a workspace.

What the image gives you

  • The full web profile over the base harness, including the built frontend
  • A healthcheck, a pinned pnpm, and native modules compiled for the image
  • Profiles, sessions, and settings persisted under /root/.dsh

Data and configuration

The container stores all harness data under /root/.dsh. Mount a volume there, or set DSH_HOME to relocate it. Set DSH_TELEMETRY_DISABLED=1 to disable telemetry.

Secure the surface

The image defaults to binding all interfaces because the web surface can run code on the host. Restrict network access to the port, or run with --host 127.0.0.1 to return to loopback.

Runnable as a pod

Set the container's exposed port (3080), a persistent volume mounted at /root/.dsh, and DSH_TELEMETRY_DISABLED=1 as needed — the same three settings as the Docker quick start above translate directly to a Kubernetes container spec, Compose service, or any other pod runtime.
